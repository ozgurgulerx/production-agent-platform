# 02 — Foundry evals for the agents you just built

Same dataset, same evaluators, pointed at whichever agent you choose: the prompt agent (F03 lab 01), a hosted agent (F03 lab 02), the workflow agent (F03 lab 03). Set `EVAL_AGENT_NAME` in `.env` to switch.

Evaluation in Foundry is the OpenAI-compatible `evals` API on the project's OpenAI client plus Foundry-specific evaluators (`builtin.*`), targets (`azure_ai_agent`), data sources (`azure_ai_target_completions`, `azure_ai_source` for live responses / traces / red-team), rules and schedules. Evaluations are GA; several evaluators, rubric generation, trace scheduling, red-team scans in the dashboard and the optimizer are preview.

## Separate environment
`agent-framework-foundry` pins `azure-ai-projects<2.8`; the surfaces here need `>=2.9`:
```bash
cd 02-evals && python3.13 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

| Step | Script | What it proves |
|---|---|---|
| 1 | `01_batch_eval_agent_target.py` | dataset upload → `evals.create` (criteria) → `evals.runs.create` against the agent target → `report_url` |
| 2 | `02_rubric_generation.py` | Foundry writes a weighted rubric from the agent definition; you version it as an evaluator |
| 3 | `03_continuous_evaluation_rule.py` | sample live responses of one agent, capped per hour; needs Foundry User on the project MI |
| 4 | `04_scheduled_trace_eval.py` | daily trace-based eval (preview) over Application Insights |
| 5 | `05_red_team.py` | cloud red-team scan against the agent target: prohibited actions, data leakage, jailbreak, base64, multi-turn |
| 6 | `06_agent_optimizer.py` | cost estimate → instruction/model candidates → score → promote if Δ > 0.03 |
| CI | `eval.yaml` | `azd ai agent eval run --config eval.yaml` as a pipeline gate |

## Reading results
- `run.per_testing_criteria_results` gives pass/fail per evaluator; `report_url` opens the row-level view.
- `{{sample.output_items}}` (tool calls included) is what agent evaluators like task adherence and tool call accuracy need; `{{sample.output_text}}` is enough for text-quality and safety evaluators.
- Rubric scores are 1–5 per dimension and normalised to 0–1 at the top level; the default threshold is 0.5.
- Optimizer score deltas: < 0.03 noise, 0.03–0.10 moderate, 0.10–0.20 significant, > 0.20 major.
