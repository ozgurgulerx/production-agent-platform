## Interview model to carry

Three agent types in Agent Service (prompt, voice prompt, hosted) plus the ephemeral agent you build in your own code against the Responses API. Seven ways to put one on Foundry: portal prompt agent; SDK/REST/azd prompt agent; voice prompt agent; ephemeral via `FoundryChatClient` or a raw OpenAI client; hosted from a source zip with remote build; hosted from a container image; self-hosted on your own compute using Foundry models and toolboxes. Everything is called through one surface, `POST /responses`; the only question is whether the definition lives in Foundry, in your container, or in your request. Multi-agent is Agent Framework workflows hosted as one hosted agent, or A2A across trust boundaries; Foundry declarative workflows retire on 1 Dec 2026.

## Breaking changes versus the Ignite 2025 demos (what foundry-demo had to change)

1. `agent.yaml` removed; `azure.yaml` is the single manifest.
2. `azure-ai-agentserver-agentframework` → `agent-framework-foundry-hosting` (`ResponsesHostServer`) or `azure-ai-agentserver-responses`; preview backend ended 20 Aug 2026.
3. Protocol `responses` version `v1`/`1.0.0` → `2.0.0`.
4. `ImageBasedHostedAgentDefinition` → `HostedAgentDefinition(container_configuration=…)`; new `create_version_from_code` zip path.
5. `AzureOpenAIResponsesClient`, `AzureAIAgentClient`, `azure.ai.agents` (threads/runs) → `FoundryChatClient`, `FoundryAgent`, `azure-ai-projects` 2.x.
6. `extra_body={"agent": …}` → `project.get_openai_client(agent_name=…)`.
7. Classic `McpTool(...).definitions` → `azure.ai.projects.models.MCPTool`; approval loop mandatory by default.
8. `WorkflowAgentDefinition` YAML workflows → Agent Framework `WorkflowBuilder` hosted as a hosted agent.
9. Agent Applications → new endpoint model; publish = M365/Teams.
10. `az cognitiveservices agent start/stop` → SDK `get_version` polling and `azd ai agent show/monitor`.
