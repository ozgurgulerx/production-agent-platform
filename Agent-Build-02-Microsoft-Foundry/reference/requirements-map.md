# Requirements and evidence map

The [curriculum mapping](curriculum-mapping.md#curriculum-mapping-and-depth) assigns all architecture requirements 1–27 and code requirements C1–C28 to a primary home and specifies depth. IDs come from the user-supplied Azure contract AI architect mastery synthesis dated 30 October 2026. Raw advertisements and private career material are not copied into this repository.

This is requirements traceability, not independent validation of each advertisement. Architecture and code scores start **unassessed**. Record the source requirement, module, exercise, permitted assistance, evidence location and remaining gap when assessing progress. Refer to the original private synthesis for detailed requirement wording.

Core priorities are architecture defence, identity, SDK fluency, permission-aware retrieval, durable tools, evaluation, operations and gateway controls. Copilot integration requires a demonstrated boundary; detailed authoring belongs in the companion section. Fine-tuning and local execution remain optional depth without deleting their existing content.

Security architecture and governance (15, 24) live in [F10](../F10-Security-and-Governance/README.md); responsible AI (7), Content Safety (C9) and red-team interpretation (C24) live in [F14](../F14-Responsible-AI-and-Safety/README.md). Shared evaluation execution remains in F08; identity and networking remain in F03 and F02. See the [production build inventory](production-capability-builds.md) for current artifacts and unverified implementation gaps.

The [preserved merged production checklist](production-build-checklist.md) and [229-item coverage matrix](production-build-coverage.md) extend the original numbered crosswalk with every documentation-derived checkbox, including nested items and unresolved placeholders. Each occurrence has its own stable ID and primary module build contract. Mapping means a study home exists, not that the capability is implemented or verified.
