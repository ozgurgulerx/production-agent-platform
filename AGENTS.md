# Repository instructions

## Learner ownership

This is a learning repository. The learner writes all functions, server adapters, and tests. Keep scaffolds empty until the learner fills them in. Agents may explain contracts, review learner work, diagnose errors, and maintain documentation, fixtures, tooling, or CI. Do not write or replace learner functions or tests unless the user expressly asks for that specific work. Do not provide hidden solutions, fabricated tests, placeholder passing tests, status claims, or xfails that make incomplete work look complete.

Stages must remain self-contained, with their own dependencies, lockfile, fixtures, source, and tests. Do not import another stage. Future roadmap stages get no folders until requested. Empty-test collection must be reported as “scaffold only—functionality unverified,” never as passing functionality. Once tests exist, run them and require at least 80% coverage. Report checks honestly.

## Changes and Git

Use main directly. Do not create branches or pull requests unless the user asks. Preserve repository history and ignored local state. Review changes and checks before publishing. Agent-authored commits must say `[agent]` in the subject, using the conventional format such as `docs: [agent] clarify stage contracts`. Never attribute agent-authored work to the learner. Do not commit secrets, credentials, personal automation, or private local artifacts.

## Local application preferences

Never launch LibreOffice or invoke soffice. Open PowerPoint files only when asked, explicitly using Microsoft PowerPoint. When asked to open a webpage or HTML report on macOS, launch Safari explicitly unless the user chooses another browser.
